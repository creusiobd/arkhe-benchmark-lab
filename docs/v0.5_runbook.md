# v0.5 Reproducible Evaluation Runbook

## Evidence status

Version v0.5 is a **development and reproducibility corpus**. Its outputs were inspected during implementation, so it is not an untouched holdout and cannot support a confirmatory claim. All v0.5 evaluations must remain labeled `integration_only`.

The pipeline proves that a clean checkout can regenerate the corpus, enforce split isolation, calibrate on validation data only, execute the detectors and produce an auditable evidence package.

## 1. Install and test

```bash
python -m pip install -e ".[dev]"
python -m unittest discover -s tests -v
```

The acceptance gate is that the complete suite passes in a clean checkout; do not hard-code a historical test count.

## 2. Regenerate and audit the corpus

```bash
python scripts/generate_v05_dataset.py
python scripts/audit_v05_shortcuts.py
python scripts/power_analysis_v05.py
```

Regeneration must preserve the hashes in `datasets/v0.5_hard/generation_manifest.json`. The shortcut audit is finite and reduces obvious leakage risk; it does not prove absence of every shortcut.

## 3. Execute the offline development rehearsal

```bash
python harness/run_v05_folds.py --semantic-mode offline_proxy --output results/v0.5_offline
python evaluator/evaluate_v05.py --run results/v0.5_offline
```

Expected labels:

- execution: `development_rehearsal_test_informed`;
- evaluation claim: `integration_only`.

Generated results are build artifacts. They are not imported from the former branch and must not be represented as external evidence.

## 4. Freeze v0.5 for reproducibility

```bash
python scripts/freeze_v05.py
```

The manifest intentionally emits `claim_eligibility: reproducibility_only` and `confirmatory_claims_allowed: false`. A freeze protects integrity; it does not erase prior inspection.

## 5. Optional OpenAI integration smoke test

Load `OPENAI_API_KEY` through local secret management and never commit credentials.

```bash
python harness/run_v05_folds.py \
  --semantic-mode openai_api \
  --model <pinned-model-id> \
  --detectors semantic_event \
  --smoke-per-partition 3 \
  --output results/v0.5_openai_smoke
```

A smoke test proves API integration only. It cannot support detector-performance claims.

## 6. Gate for a future confirmatory study

A confirmatory run must use a new version such as v0.6 and a test sample whose outcomes were not inspected during tuning. Before the first held-out execution:

1. freeze the primary hypothesis and endpoint;
2. freeze corpus generation inputs, splits, detector code and thresholds;
3. record hashes and the reviewed source commit;
4. prohibit tuning on test-family outputs;
5. retain null, negative and high-false-positive results;
6. have an independent operator reproduce the package.

Until then, the correct statement is: **reproducible internal laboratory evidence, not real-world validation**.
