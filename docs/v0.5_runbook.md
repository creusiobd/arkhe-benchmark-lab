# v0.5 Reproducible Evaluation Runbook

## 1. Install and test

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

The current acceptance gate is 192 tests passing with one credential-dependent test skipped.

## 2. Regenerate and audit the corpus

```bash
python scripts/generate_v05_dataset.py
python scripts/audit_v05_shortcuts.py
python scripts/power_analysis_v05.py
```

Regeneration must preserve all three hashes in `datasets/v0.5_hard/generation_manifest.json`. The shortcut audit is a declared finite test, not proof of complete absence of leakage.

## 3. Development rehearsal

```bash
python harness/run_v05_folds.py \
  --semantic-mode offline_proxy \
  --output results/v0.5_offline
python evaluator/evaluate_v05.py --run results/v0.5_offline
```

Runs without a verified freeze manifest are marked `development_rehearsal_test_informed` and their evaluation is labeled `integration_only`.

## 4. Freeze for reproducibility

Commit the protocol, corpus, detector, calibration, harness, and evaluator. From a reviewed source commit:

```bash
python scripts/freeze_v05.py
git add freezes/v0.5_freeze.json
git commit -m "chore: freeze v0.5 confirmatory evaluation"
```

The current v0.5 outputs were inspected during development before the freeze. Therefore this freeze records content hashes and blocks mismatches, but is explicitly `reproducibility_only`; it does not retroactively make v0.5 confirmatory.

## 5. Frozen offline reproducibility control

```bash
python harness/run_v05_folds.py \
  --semantic-mode offline_proxy \
  --freeze-manifest freezes/v0.5_freeze.json \
  --output results/v0.5_frozen_offline
python evaluator/evaluate_v05.py --run results/v0.5_frozen_offline
```

This validates the pipeline but the semantic detector remains a heuristic proxy, and the run is labeled `frozen_reproducibility_run`.

## 6. Live OpenAI integration smoke test

Load `OPENAI_API_KEY` through local secret management; never place it in YAML, logs, manifests, or commits.

```bash
python harness/run_v05_folds.py \
  --semantic-mode openai_api \
  --model gpt-4o-mini-2024-07-18 \
  --detectors semantic_event \
  --smoke-per-partition 3 \
  --output results/v0.5_openai_smoke
```

Smoke output is always marked `smoke_test` and cannot support performance claims.

## 7. Future confirmatory live run

Create a new version and fresh evaluation sample whose test outputs have never been inspected. Freeze that version before any held-out execution. Only a manifest with `claim_eligibility: prospective_confirmatory` may produce a confirmatory status. The current v0.5 manifest intentionally does not.

The execution command for an eligible future freeze is:

```bash
python harness/run_v05_folds.py \
  --semantic-mode openai_api \
  --model gpt-4o-mini-2024-07-18 \
  --freeze-manifest freezes/<fresh-version>_freeze.json \
  --output results/<fresh-version>_openai_confirmatory
python evaluator/evaluate_v05.py --run results/<fresh-version>_openai_confirmatory
```

Repetition 1 is primary. Repetition 2 is repeatability only. Do not pool them as 240 independent trajectories.

## 8. Interpretation gate

Before publication, verify:

- test thresholds came only from each fold's validation mechanisms;
- every trajectory appears in a test family exactly once per repetition;
- Task A and Task B remain separate;
- raw numerators/denominators and Wilson intervals are present;
- near-violation and benign negative strata are not collapsed in narrative claims;
- results are described as synthetic internal family-held-out evidence;
- null or negative findings are preserved.
