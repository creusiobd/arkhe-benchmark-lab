# ARKHÉ v0.6 — preregistration before evidence

**Current stage:** design only  
**Claim eligibility:** none  
**Test data:** not generated and not committed  
**Confirmatory claims:** prohibited

## Why v0.6 exists

The v0.5 pipeline now proves internal reproducibility, but its outputs were inspected during development. It cannot be transformed retroactively into confirmatory evidence. v0.6 starts from the opposite direction: first decide, then freeze, only then observe.

## Primary research question

Does trajectory-aware analysis improve timely pre-violation classification over one frozen event-level comparator on previously unseen agent-security cases?

There will be one primary hypothesis and one primary endpoint. Additional metrics remain descriptive or secondary.

## Decisions that must be closed before freeze

| Decision | Current state | Freeze requirement |
|---|---|---|
| Evidence source | Open | Independent synthetic authoring or authorized external retrospective cases |
| New scenario families | Open | At least four; none may reuse the three v0.5 families |
| Sample size | Open | Justified before generation through a sensitivity/power plan |
| Primary comparator | Open | Exactly one: deterministic or semantic event detector |
| Minimum relevant effect | Open | Defined in percentage points before test access |
| Semantic model | Open | Exact supported model snapshot recorded |
| Missing-data rule | Open | Deterministic rule written before execution |
| Stopping rule | Open | No optional stopping after inspecting outcomes |
| Test custodian | Open | Person or independent process separated from detector tuning |
| Sealed manifest | Open | SHA-256 commitment recorded before unblinding |
| Approver | Open | Named reviewer accepts the frozen protocol |

## Phase gates

### D0 — Design

Allowed:

- edit the research question and protocol;
- run unit tests on contracts;
- perform sensitivity calculations without test outcomes;
- select an independent data author/custodian.

Prohibited:

- create or inspect v0.6 test trajectories;
- commit v0.6 labels, predictions, evaluations or results;
- tune the detector against v0.6 cases;
- use confirmatory language.

### D1 — Ready to freeze

The command below must pass with no unresolved fields:

```bash
python scripts/validate_v06_preregistration.py --require-freezable
```

A reviewer then records the exact source commit, protocol hash, model ID, sample plan, custodian and sealed test-manifest hash.

### D2 — Frozen and blind

Only after the freeze commit may the independent custodian construct or release the committed test package. Developers may not inspect labels or predictions before the declared unblinding condition.

### D3 — Executed once

Repetition 1 is primary. Later repetitions measure repeatability and are not pooled as new independent evidence. Null results, failed gates and excessive false positives remain part of the record.

## Separation of roles

| Role | May see detector internals | May see test labels before lock | Responsibility |
|---|---:|---:|---|
| Detector developer | Yes | No | Implement frozen detector |
| Data author/custodian | No preferred | Yes | Construct and seal test package |
| Evaluator | No tuning authority | At execution | Run frozen protocol |
| Approver/reviewer | Read-only | Hashes before unblinding | Verify integrity and deviations |

## Immediate next action

Resolve the open decisions in the protocol. Do not generate data yet. The fastest path is not the one that runs first; it is the one that leaves the fewest doors open for self-deception.
